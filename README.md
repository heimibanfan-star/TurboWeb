## TurboWeb是什么？

**TurboWeb** 是一个现代、高性能、无废话的 Java Web 框架，底层基于 Netty，核心依托 **JDK 21 虚拟线程（Loom）**，为高并发场景而生。它不仅运行得飞快，还写得极爽——

你写的，是再普通不过的同步 Java 代码；
你收获的，是让异步框架都汗颜的吞吐性能。

不再需要回调、响应式、链式 API，也不必掌握 Mono、Flux 或什么“编排式编程”。路由用 `@Route`、`@Get` 声明，形参用取参注解直接声明业务类型，剩下的，都交给 TurboWeb。

## 为什么选择TurboWeb？

**_高度可定制_**

请求处理的每个环节都留了扩展接口：中间件链、参数解析器、内容解析器、JSON 序列化器、异常处理器、会话管理器都可以注册或替换，任务卸载执行器也可整体接管，默认实现覆盖常规场景，需要改行为时不必修改框架源码。

**_同步开发体验，异步级性能_**

TurboWeb 全面基于 **虚拟线程** 执行请求处理，不再使用传统线程池。每个请求拥有独立线程，上万并发依旧从容，开发体验丝滑如春风。

**_长连接原生支持_**

SSE 原生集成，无需第三方依赖即可构建推送类应用，底层生命周期由 Netty 驱动，性能轻盈又稳定。WebSocket 由独立的 `WebSocketServerRuntime` 接入，与 HTTP 应用共用同一条连接管道。

**_注解路由与注解取参_**

`@Route` 声明类前缀，`@Get`、`@Post` 等方法声明请求方式与路径；形参用 `@PathParam`、`@QueryParam`、`@BeanJson` 等注解直接声明业务类型，不必从上下文手工取数。框架通过**方法句柄**调用控制器，路径与参数在构建期完成校验。

**_流式背压闭环_**

响应写出自带背压控制：写出通道来不及消费时，上游暂停产出，通道恢复可写后自动续推。慢客户端与大响应体场景下内存占用有上界，流式推送与高并发长连接不靠堆缓冲硬扛。

**_消息化响应写出管线_**

返回值统一装配为响应消息后，按消息类型路由到专用写出处理器：字节、JSON、chunked 流式与 SSE 各有内置写出方。同一条连接上的响应按序列定序写出，写出失败自动关闭通道，保证高并发下响应不交错。文件响应由 `HttpResult.fileOf` 一行声明，文件名自动按 RFC 5987 编码，中文文件名跨浏览器可靠。

**_最简启动，极速响应_**

无需 XML，无需扫描 classpath，几行代码即可跑通请求流程。框架启动只需百毫秒，占用几十 MB，适合快速开发、小型部署，也适合重型分布式集群服务。



**TurboWeb**，不只是一个框架，更是一种**”用同步思维写异步应用”**的全新范式。

## 本版本变更说明

2.6.x 对响应写出体系与模块划分做了一次整体重构，请求处理链路的形态与扩展点都有调整，部分旧写法不能直接编译通过。升级前建议对照以下各条，各章文档开头的“变更说明”记录了对应范围的细节。

- 响应体系全面消息化：`HttpResult` 重写为值对象，只承载状态行、响应头与原始业务数据，由结果转化环节统一装配为响应消息；消息契约上移到 `turboweb-http-core`，头部收编为独立的 `Headers` 实体，状态行携带标准短语，旧的 `Content` 接口、响应对象与写出器链下架。返回值装配口径固定：String 按 text/html、byte[] 原样写出、Publisher 走 chunked 流式、其余对象经 JSON 序列化，自定义结果转化器入口不再开放。
- 文件响应统一走 `HttpResult.fileOf`：一行声明字节内容、内容类型与文件名，支持附件下载与内联展示两种方式；文件名含非 ASCII 字符或引号、反斜杠时自动追加 RFC 5987 的 filename* 扩展参数，中文文件名在各浏览器下可靠；零拷贝文件传输与 `AsyncFileResponse` 下架。
- 响应写出改为处理器路由：写出器按消息类型与消息声明的写出处理器路由写出；未携带 Content-Type 的消息与找不到处理器的消息降级写出报错页，报错页继承原响应的非实体头；文本类声明缺 charset 段时补写缺省字符集，二进制类型不补编码；同一条连接上的响应按序列定序写出，写出失败自动关闭通道防止响应交错，流式写出带背压控制。
- SSE 统一为 `SseEmitter`：事件经内部缓冲投递，缓冲容量可调，连接关闭可监听；旧的 `SseResponse` 与旧发射器下架。
- 请求与 WebSocket 消息的执行统一收口到微任务执行器（`MicroTaskExecutor`）的虚拟线程实现，调度限流按需限制并发虚拟线程数；应用可传入自定义执行器实例接管任务卸载。
- 连接管理增强：新增连接空闲回收，空闲阈值由 `ServerConfig` 的 `idleCloseTime` 配置，WebSocket 等长生命周期协议升级后自动豁免回收。
- 应用装配入口收敛为 `HttpServerRuntime.builder()`：中间件、内容解析器、JSON 序列化器、异常处理器、会话管理器、CORS 配置与任务卸载执行器都在此注册，服务器启动入口 `BootStrapWebServer` 保持不变；旧的 `HttpRequestApplication` 下线。
- 模块按域重组：`turboweb-server` 更名 `turboweb-http-server`，HTTP 消息契约拆入 `turboweb-http-core`，服务器运行时契约与资源管理拆入 `turboweb-server-runtime`，`turboweb-common` 下架、能力并入使用方模块。
- WebSocket 模块重构：处理器基类更名为 `WebSocketHandler`，事件回调统一 Frame 后缀，新增裸帧处理器 `UnSafeWebSocketHandler`，会话不再提供属性挂载入口，异常收敛为 `WebSocketException`。
- HTTP 客户端完成响应式引擎重构（`ReactiveHttpClientEngine` 与 `RestHttpClient` 门面），移除 httpcore5 依赖；本版本客户端暂不推荐用于生产。

## 本版本特色

- **流式背压闭环**：响应写出自带背压控制，写出通道来不及消费时上游暂停产出，通道恢复可写后自动续推；慢客户端与大响应体场景下内存占用有上界，流式推送不靠堆缓冲硬扛。这是 2.6.x 响应写出体系的最大特色。
- **消息化响应写出管线**：返回值统一装配为响应消息后按类型路由到专用写出处理器，Content-Type 门禁、字符集补写、降级报错页与同连接响应定序在管线内闭环，写出失败自动关闭通道。字节、JSON、chunked 流式与 SSE 多种响应形态开箱可用。
- **文件响应一行声明**：`HttpResult.fileOf` 声明字节内容、内容类型与文件名即可产出下载或内联响应；文件名自动按 RFC 5987 编码，中文与特殊字符跨浏览器可靠。
- **微任务执行器统一调度**：请求处理与 WebSocket 消息都运行在虚拟线程微任务执行器上，同步写法直写阻塞 I/O；调度、限流与任务卸载经执行器抽象统一收口，可整体替换为自定义实现。
- **长连接原生支持**：SSE 由 `SseEmitter` 驱动，事件缓冲容量可调、连接关闭可监听；WebSocket 由独立的 `WebSocketServerRuntime` 接入，与 HTTP 应用共用同一条连接管道；连接空闲回收自动清理僵死连接，长生命周期协议自动豁免。
- **注解路由与方法句柄调用**：路径、请求方式、取参全部由注解声明，构建期生成调用链，运行期不做反射查找。
- **高度可定制**：中间件、参数解析器、内容解析器、JSON 序列化器、Bean 校验器、异常处理器、会话管理器、任务卸载执行器都开放注册或替换，默认实现覆盖常规场景，改行为不必动框架源码。
- **请求体先解析后绑定**：请求体按 Content-Type 在路由匹配前解析为内容对象，参数绑定器按内容类型取数；新类型只需补一条内容解析器。
- **构建期校验**：路由冲突、重复注册、参数解析器与内容解析器冲突都在启动装配时暴露，不会拖到运行期才报错。
